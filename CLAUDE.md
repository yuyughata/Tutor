# Genova (by CUSTAR) — working context

Children's storybook app. Text stories now; audio then video later. CUSTAR authors first, outside writers later.
Read `README.md` for setup, `docs/MVP_BRIEF.md` for scope, `docs/HANDOFF.md` for accounts/secrets/deploy/resuming in a new chat or account, and `tools/qa/README.md` for the browser test tooling. This file holds decisions, conventions and the backlog so a new session can continue without re-deriving them.

## Product decisions (do not re-litigate)
- **Reading levels, never ages.** Sunrise = Assisted Reader, Spark = Emergent Reader, Seeker = Developing Reader. No age or age-group text may appear in the app, website, admin or docs. DB enum is `reading_level` (`sunrise|spark|seeker`).
- **Payments on the web only** (Paystack). The app shows no prices and no purchase buttons; it links to the website behind the parental gate.
- **Plans:** Free; Paid ₦3,000/month; ₦7,500/quarter (changed from ₦5,000 / ₦12,000 on 2026-10-11; update the Paystack plan amounts to match) (table `plans`).
- **Access rule (single source of truth in the DB, `my_access()` + hourly expiry job):** active/trialing/past_due keep Premium until `current_period_end` + 5 days, then Free. Cancelled keeps access until period end. Active with no end date = complimentary.
- **Brand:** purple `#ab46d2`, teal `#10a19c`, amber `#ffbe00`, charcoal `#232323`; font Nunito. Use charcoal (not white) text on teal/amber and `purpleDeep`/`tealDeep`/`amberDeep` for small coloured text (contrast).
- Parents have accounts (created on the website); children are reader profiles on the device (name/nickname, avatar, level only).
- Privacy policy text lives in `legal_documents` (slug `privacy-policy`), edited by admins, shown in the app (pop-up) and on the website. Current text is SAMPLE.

## Conventions and gotchas
- Supabase client uses `db: { retry: false }`; catalogue is cache-first (AsyncStorage) so offline fallback is fast.
- Decorative images are `aria-hidden` (expo-image drops `alt=""`); keep zero axe WCAG A/AA violations.
- Supabase MCP tool: statements containing DROP/DELETE stall waiting for confirmation, and calls time out at 60s. Use `ALTER POLICY ... rename`, avoid those words, split migrations into small chunks. Policies call `private.is_admin(...)`.
- Sandbox cannot reach `*.supabase.co`, `paystack.com` or CDNs. Test with a fake backend that speaks the real Supabase wire format (Playwright route mocks), axe-core for accessibility, and rollback-only SQL tests (`raise exception` inside DO blocks with simulated JWT claims).
- Shell: do not `pkill -f` / `pgrep -f` with a pattern that matches your own command line (use `[h]ttp-server` style or a PID).
- Commit messages end with the Co-Authored-By and Claude-Session lines. Develop on `claude/gifted-brahmagupta-a0jtkt`; do not open a PR unless asked.

## Song (built 2026-10-11; migration 0009 applied live)
One optional **MP3 song per story** (MP3 only, no YouTube). It **unlocks on The End** (never midway) and plays only when the child taps it.
- DB: `stories.song_path / song_title / song_seconds / song_bytes`; private bucket `songs` (`<story_id>/<uuid>.mp3`, 3 MB cap, `audio/mpeg`), admin write policy and a read policy that reuses `private.can_read_story` (so a Premium story's song is not reachable without access). Rollback-only check: `supabase/tests/song_access.sql`.
- **Admin** (`web/public/admin/js/audio.js`, Song card in `views/editor.js`): the MP3 is made light **in the browser before upload**: decode (Web Audio), mono, 24 kHz, 48 kbps via vendored lamejs (`js/vendor/lame.min.js`, LGPL, licence file beside it). 3 min ≈ 1 MB. Limits: 40 MB source, 5 min. Shows before/after size, duration and a preview player; title is prefilled from the file name; checklist item "Song has a title" appears when a song is set. `api.uploadSong` / `api.songUrl` (demo parity in `demo.js`); saving removes superseded files from the bucket.
- **App**: `getSong(story)` in `repository.ts` (signed URL, or the saved local file); `src/lib/song.ts` `useSongPlayer` (expo-audio; created with the reader, `replace({uri})` as soon as reading starts so the file is loaded before The End; pauses on app background and when leaving The End; no background playback, no autoplay). `SongHint` pill on a few pages only (`songHint()` in `lib/story.ts`: first page, middle of a 5+ page story, last page), `SongCard` on The End (play/pause, progress, time; "Getting your song ready…" until loaded). If the song cannot be fetched there is no hint and no card. Story page shows a "Has a song" fact. Offline: `saveStory(..., song)` downloads `song.mp3` on phones/tablets (`SavedStory.song`).
- **Native build needed**: `expo-audio` is a new native module (like the kiosk module), so phone apps need a fresh EAS build; Expo Go may not have it. Web, website and tests are unaffected. Not yet run on a physical device.
- Tests: `tools/qa/song-e2e.cjs` (hints, preload before The End, tap-to-play, axe), the admin Song step in `admin-new.cjs`, `songHint`/`clock` in `app/tests/story.test.mjs`, admin API tests for song fields. Mock backend serves a generated tone (needs `ffmpeg`).

## Offline sign-in (2026-10-13)
`src/state/auth.tsx` keeps a parent signed in while offline. supabase-js returns **no session** when the access token (1 h) has expired and the refresh cannot reach the server (it retries for ~30 s first), although the sign-in is still in storage; the app used to treat that as signed out. Now the stored session (`storedSession()` in `src/lib/supabase.ts`, same `sb-<host>-auth-token` key) shows at once, `getSession()` confirms it, a null session that is not an explicit `SIGNED_OUT` falls back to the stored one, the access check (`my_access`) falls back to the remembered answer after 4 s (a late real answer still replaces it), sign-out works offline (`scope: 'local'` fallback), and the token refreshes when the network or the app comes back. Only a real sign-out or a rejected refresh token signs the parent out. Test: `tools/qa/offline-session-e2e.cjs`. Premium stories that were not saved still need a connection to open; saved ones open offline.
