Paystack set-up and payment plans

How parents pay on the website, what is already configured, and what you still need to do. Prepared 15 October 2026.

1. How payments work

  • Parents pay only on the website (www.custar.ng/Genova). The app shows no prices and no purchase buttons.
  • The parent picks a plan, ticks the privacy-policy consent, and is sent to Paystack's secure payment page. Card details never touch Genova.
  • Paystack charges the amount set on the Paystack plan, then repeats the charge every month or quarter.
  • Paystack tells Genova about each payment through a webhook. Genova then turns Premium on, keeps it on while payments continue, and sends the receipt and reminder emails.
  • Parents manage or cancel their subscription from the Account page on the website. A cancelled plan keeps Premium until the end of the paid period.

3. Paystack dashboard set-up

3.1 Create the plans (done)

  1. Paystack dashboard, Plans, Create Plan.
  2. Name Genova Premium Monthly, amount ₦3,000, interval Monthly. Leave the invoice limit blank so it renews until cancelled.
  3. Name Genova Premium Quarterly, amount ₦7,500, interval Quarterly. Same settings.
  4. Copy each plan's code (starts with PLN_). These are the codes in section 2.

3.2 Webhook

  1. Paystack dashboard, Settings, API Keys & Webhooks.
  2. Set the Webhook URL (use the same URL in Test and Live mode) to:
    https://cjdrlddvbyfataumdztg.supabase.co/functions/v1/paystack-webhook
  3. Save. This URL must point at the Genova Supabase function, not at another website.

Genova checks the signature on every webhook with your secret key, so anyone posting to that URL without Paystack's signature is ignored.

3.3 API keys

On the same page copy the Secret Key (starts with sk_test_ or sk_live_). Never put it in the website, the app or a document. It goes only into Supabase (next section).

5. Test before going live

  1. Use Paystack Test mode: test secret key in Supabase, and test-mode copies of both plans (test and live plans have different codes).
  2. On the website create a parent account, open Plans, choose Premium Monthly, tick the consent and continue to Paystack.
  3. Pay with a test card from Paystack's documentation (https://paystack.com/docs/payments/test-payments).
  4. You return to the Account page. It should show the Premium badge and the renewal date. Open the app signed in to the same account: the premium stories are unlocked.
  5. In Supabase, table payment_events should contain the webhook events. This confirms Paystack's data matches what Genova expects.
  6. Check that the receipt email arrives (needs email activated in the admin).
  7. Try Manage subscription and cancel. Premium should stay until the end of the paid period.
  • Plan amounts are ₦3,000 and ₦7,500 in Paystack
  • Webhook URL saved in Paystack
  • PAYSTACK_SECRET_KEY and WEB_URL set in Supabase
  • Test payment shows the Premium badge
  • payment_events has rows
  • Receipt email arrives

6. Going live

  1. Complete Paystack's business verification so live payments are enabled.
  2. Create the same two plans in Live mode (₦3,000 monthly, ₦7,500 quarterly). The live plans have new PLN_ codes. Send them to be saved in the database.
  3. Replace the Supabase secret PAYSTACK_SECRET_KEY with the live secret key.
  4. Check the webhook URL is set under Live mode too.
  5. Make one real small payment and cancel it, to confirm the full cycle.

Changing a price later: edit the plan in Paystack (it offers to update existing subscribers or not) and change the price in the Genova plans table so the website shows the same amount.

7. If something goes wrong

What you seeLikely cause and fix
"Payments for this plan are not set up yet"The plan has no Paystack code. Codes are saved for both plans, so check the plan is marked active.
"Could not start checkout" or a Paystack errorSecret key missing, wrong mode (test key with live plan, or the reverse), or the plan code does not exist in that mode.
Parent paid but is not PremiumWebhook not reaching Genova. Check the webhook URL, then Paystack's webhook log and the payment_events table.
Wrong amount chargedThe amount on the Paystack plan is wrong. Fix it in Paystack.
Parent returned to the wrong siteWEB_URL is missing or wrong.
